Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это практически просто указатель на определённый commit. Создание ветки выполняется быстро и почти не требует дополнительного места. Поэтому можно часто создавать и удалять ветки для разных задач.

В SVN ветка обычно представляет собой отдельную копию каталога в репозитории. Создание ветки связано с операцией копирования и управлением этой отдельной веткой, поэтому ветвление исторически считалось более тяжёлой операцией.

Можно ли в SVN сделать коммит без интернета? Почему?
Обычно нет, если SVN-репозиторий находится на удалённом сервере. SVN — централизованная система: для commit клиент должен связаться с центральным репозиторием.

Локально можно изменять файлы и выполнять некоторые операции, но полноценный commit в удалённый репозиторий без доступа к нему сделать нельзя.

В Git наоборот: репозиторий полностью хранится локально, поэтому можно делать commits, создавать ветки и просматривать историю без интернета, а потом выполнить push.

В каких сценариях SVN до сих пор может быть предпочтительнее Git?
SVN может быть удобен, когда:
нужен централизованный контроль над репозиторием;
команда привыкла к модели «один центральный сервер»;
важно ограничивать доступ к отдельным каталогам;
проект использует большие бинарные файлы и существующую инфраструктуру SVN;
организация уже имеет большую систему, построенную вокруг SVN, и переход на Git не даёт существенной выгоды.
